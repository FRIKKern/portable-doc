# Portable Doc · Sunday 22 November 2026

5 pull requests merged. Four brought Barkpark's format changes here, by the hourly sync from Barkpark, the format's source until it moves here. One gave this README its News block ([#151](https://github.com/FRIKKern/portable-doc/pull/151)). This is the repo's first news day.

## What a person can now do

**A callout's body survives source mode** ([#149](https://github.com/FRIKKern/portable-doc/pull/149)). The synced editor now keeps a callout's body when a Paper is edited as source. The word test counts the words each writer loses on the shared cases: "editor source: a callout body" fell from 76 to 4. The 4 left, "Read the guide first", sit in a callout under a list item, where source mode still cannot hold a block.

**Deep nested inline keeps its word** ([#150](https://github.com/FRIKKern/portable-doc/pull/150)). Under a mark or a bare list at the inline depth limit, React here now draws the words flat, then "Nested too deep to show", where it wrote only the notice. Six limit goldens changed this way, and one is new: em past the value depth.

**A list item one block past the limit shows the notice** ([#153](https://github.com/FRIKKern/portable-doc/pull/153)). Barkpark's readers now write "Nested too deep to show" inside the deepest item, as React here already did. So React writes that golden byte for byte, and the list of limit goldens React does not yet write is empty: its cap went from 1 to 0.

To check any sync, rerun `node scripts/sync-from-barkpark.mjs` at the named Barkpark commit in your own tree. The diff against the PR's first commit must be empty.
