# 0006 One MCP server: validate, explain, apply ops, render through Barkpark

Date: 2026-11-01 · Status: accepted

```
MCP client ──stdio (BoundedStdioTransport: 16 MiB, every line answered)──► Server (SDK 1.32.1, low level)
   │
   ├─ validate   @portable-doc/validate, unchanged
   ├─ explain    path → "block 2 (section) › field …", rule ← packages/validate/CODES.md
   ├─ apply_ops  lowerEditorOp ─► applyPatch, per op, all or nothing
   │               ported from Barkpark: Patch (6 ops, whole) · BlockOps.lower_editor_op + TableEditing (3 intents, strict subset)
   └─ render     POST $BARKPARK_URL/v1/plugins/bulldocs/render {title?, blocks} ─► {html}
```

## Context

R4.4 asks for an MCP server an agent can use to check, fix and see a doc. Barkpark owns the op semantics (`api/lib/barkpark/portable_doc/patch.ex`, plus `BlockOps.lower_editor_op/2` and `TableEditing` for the card and table intents) and pins them with the nine op goldens. Barkpark's reader renders only stored papers (`/papers/:slug`); no route renders a doc it is handed.

## Decision

- **Low-level `Server` from `@modelcontextprotocol/sdk`, pinned to 1.32.1**, the newest release at least two weeks old on 2026-11-01 (1.32.2 is from 2026-10-23). Tools check their own arguments: missing, unknown or wrongly typed is `InvalidParams` with a message that names the argument. A `tools/call` whose params are not `{ name, arguments: {…} }` is `InvalidParams` in the SDK's words, naming the field. A refused op or a failed render is a tool result with `isError`.
- **Own stdio transport.** The SDK's closes the connection on a message over 10 MB and drops a line that is not JSON-RPC without an answer, so the client waits forever. `stdio.js` answers every line: `ParseError`, `InvalidRequest`, or for an oversize message `InvalidRequest` under the id it finds at the head or tail of the line, then keeps reading.
- **Limits before any walk.** 200,000 JSON values per call, counted without recursion. `apply_ops` and `render` refuse more than 1,000 JSON levels, because `JSON.stringify` overflows near 8,000 and an echoed doc would never reach the client. `validate` takes any depth: it stops at `MAX_DEPTH` and answers `too_deep`. At most 100 ops per call bounds the worst case (100 ops on the largest doc, below). A table edit runs Barkpark's normalizer over the whole doc, and the normalizer decodes JSON held in strings (legacy list items), so for a call with a table edit the JSON inside any string that starts with `[` or `{` counts toward both limits; a string that decoded 200,000 levels deep overflowed the stack before this.
- **Answers stay in proportion to the call.** Every walk is linear. Barkpark's `normalize_render_shapes` runs its leaf pass once per enclosing level, so a block 480 levels down gets it 480 times, and that pass is not idempotent (a text node with `text` converts and stops; its children convert on the next pass; list items unwrap one level per pass). The port counts the passes and applies them in one walk (`ops/persist.js`: `passes`, `lift`); the old literal port took 220 s for 100 table edits over 60,000 tables 480 sections deep. A string the normalizer decodes is parsed once per process, not once per edit (a memo of up to 32 MiB of strings): a 14 MB string that fails to parse on its last character cost 8–11 s for 100 edits before, 0.3 s now. The worst shapes (wide locked docs, many same-id tables, a 495-deep chain, 60,000 tables 480 levels deep, mark chains and wrapper chains 240 deep inside blocks 240 deep) answer 100 ops on the largest doc in 3 to 8 s on a shared machine at load 22. `explain` cuts a location to 1,000 characters (keys, types and ids at 100), so a 10 MB call answers about 25 MB, not hundreds.
- **apply_ops is a port, checked four ways.** Every op golden's `before` plus `op` gives exactly its `after`. `differential.mjs` runs the six Patch ops on 20,000 seeded random docs through both this port and Barkpark's compiled `patch.ex`: 0 mismatches, every outcome reached. It also records a digest of each of `patch.ex`'s answers on 5,000 seeded cases (`test/patch-elixir.json`, 75 KB), and `npm run check` replays them without Elixir. `--intents` does the same for the three editor intents against `BlockOps.lower_editor_op` in a compiled Barkpark app (`test/intents-elixir.json`); the whole-doc table check is a full port of `table_normalization_safe` (`ops/persist.js`: `ensure_block_ids`, then `normalize_render_shapes`, then compare every table). `--normalize` compares `normalize_render_shapes` and the table preflight themselves on seeded shape docs (legacy lists, tables, floats, chardata styles, tables nested in other blocks): 0 mismatches on 20,000 docs each for seeds 1, 2, 31 and 77, a fifth of them deep docs that need many leaf passes, and `test/normalize-elixir.json` replays 5,000. Where no input can tell the difference it keeps only the decision: a minted id is a marker, not Barkpark's `<prefix>-<index>`. Seeded sweeps in `npm run check` prove no input throws or is mutated.
- **render needs Barkpark's reader to take a doc.** The route above is FRIKKern/barkpark#25042, merged as `f5c75aa`: read-only, a 2 MiB body cap, a 16 MiB HTML cap, and a 422 with every violation for a broken doc. Tests and `TRANSCRIPT.md` use `test/fake-reader.mjs`, which answers with the golden pack's `expectedHtml` and refuses any block that is not a golden. `LIVE.md` is the same steps against guerrilla on 2026-11-02: 200 in 161 ms, with HTML byte-equal to the fake reader's. `BARKPARK_URL` is config, never an argument, so a model cannot point the server at another host. Neither it nor `BARKPARK_TOKEN` is ever echoed: a URL with a user or password, or a token that is not printable ASCII without spaces, is refused by name before any request.

## Where the port differs from Barkpark

| Case | Barkpark | Here |
|---|---|---|
| `patch-block` whose id resolves to a non-object block (`id: null`) | raises `BadMapError` | `invalid_op` |
| `1.0` where an integer is required (table row or column) | refused (`is_integer`) | accepted: JSON.parse cannot tell `1.0` from `1` |
| `field-number` text past 2^53 | exact bignum | nearest float |
| a legacy list `style` or `listStyle` that is a map, a float, or a list that is not chardata, in a doc that gets a table edit | raises (`Protocol.UndefinedError`, `ArgumentError`, `UnicodeConversionError`) | `invalid_op` |
| a number the normalizer writes as text that is an integer-valued float (`1.0`) or an integer past 2^53 | `"1.0"`, exact digits | `"1"`, the nearest float's digits; a table it writes into changes either way, so no answer differs |
| a table edit on a doc whose strings decode to more than 200,000 JSON values or 1,000 levels | answers | `InvalidParams`: the limits count that JSON |
| more than 32 locked blocks displaced by one op | names one in hash order | names the smallest id |
| table cells with opaque keys (shape `v: 2`) | merged | read-only: the intent is `invalid_op` |
| constraint declarations (`opts[:constraints]`) | only when a caller passes them | never; the golden harness passes none either |

## Considered

- **`McpServer` with zod schemas.** Rejected: a schema miss comes back in the SDK's words instead of naming the argument, and the size, depth and doc-shape checks are needed anyway.
- **Copy legacy `packages/mcp-server` (tag `legacy-v0.4`).** Rejected: its tools sit on the old 10-type core and render locally. Kept from it: one stdio bin, tools as plain functions the server wraps, forwarding config from env.
- **render by slug (`GET /papers/:slug`).** Rejected: it renders a stored paper, not the doc the agent just edited.
- **render locally from the goldens.** Rejected: that is not Barkpark's reader (Z9).
