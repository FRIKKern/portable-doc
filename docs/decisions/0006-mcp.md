# 0006 One MCP server: validate, explain, apply ops, render through Barkpark

Date: 2026-11-01 · Status: accepted

```
MCP client ──stdio (BoundedStdioTransport: 16 MiB, every line answered)──► Server (SDK 1.32.1, low level)
   │
   ├─ validate   @portable-doc/validate, unchanged
   ├─ explain    path → "block 2 (section) › field …", rule ← packages/validate/CODES.md
   ├─ apply_ops  lowerEditorOp ─► applyPatch, per op, all or nothing
   │               ported from Barkpark: Patch (6 ops, whole) · BlockOps.lower_editor_op + TableEditing (3 intents, strict subset)
   └─ render     POST $BARKPARK_URL/v1/plugins/bulldocs/render {title?, blocks} ─► {html}
```

## Context

R4.4 asks for an MCP server an agent can use to check, fix and see a doc. Barkpark owns the op semantics (`api/lib/barkpark/portable_doc/patch.ex`, plus `BlockOps.lower_editor_op/2` and `TableEditing` for the card and table intents) and pins them with the nine op goldens. Barkpark's reader renders only stored papers (`/papers/:slug`); no route renders a doc it is handed.

## Decision

- **Low-level `Server` from `@modelcontextprotocol/sdk`, pinned to 1.32.1**, the newest release at least two weeks old on 2026-11-01 (1.32.2 is from 2026-10-23). Tools check their own arguments: missing, unknown or wrongly typed is `InvalidParams` with a message that names the argument. A `tools/call` whose params are not `{ name, arguments: {…} }` is `InvalidParams` in the SDK's words, naming the field. A refused op or a failed render is a tool result with `isError`.
- **Own stdio transport.** The SDK's closes the connection on a message over 10 MB and drops a line that is not JSON-RPC without an answer, so the client waits forever. `stdio.js` answers every line: `ParseError`, `InvalidRequest`, or for an oversize message `InvalidRequest` under the id it finds at the head or tail of the line, then keeps reading.
- **Limits before any walk.** 200,000 JSON values per call, counted without recursion. `apply_ops` and `render` refuse more than 1,000 JSON levels, because `JSON.stringify` overflows near 8,000 and an echoed doc would never reach the client. `validate` takes any depth: it stops at `MAX_DEPTH` and answers `too_deep`. At most 100 ops per call bounds the worst case (100 ops on the largest doc, below).
- **Answers stay in proportion to the call.** Every walk is linear; the worst shapes (wide locked docs, many same-id tables, a 495-deep chain) answer 100 ops on the largest doc in about 4 s. `explain` cuts a location to 1,000 characters (keys, types and ids at 100), so a 10 MB call answers about 25 MB, not hundreds.
- **apply_ops is a port, checked four ways.** Every op golden's `before` plus `op` gives exactly its `after`. `differential.mjs` runs the six Patch ops on 20,000 seeded random docs through both this port and Barkpark's compiled `patch.ex`: 0 mismatches, every outcome reached. It also records a digest of each of `patch.ex`'s answers on 5,000 seeded cases (`test/patch-elixir.json`, 75 KB), and `npm run check` replays them without Elixir. `--intents` does the same for the three editor intents against `BlockOps.lower_editor_op` in a compiled Barkpark app (`test/intents-elixir.json`); the whole-doc table check is a full port of `table_normalization_safe` (`ops/persist.js`: `ensure_block_ids`, then `normalize_render_shapes`, then compare every table). Seeded sweeps in `npm run check` prove no input throws or is mutated.
- **render needs Barkpark's reader to take a doc.** The route above does not exist yet; it is a small, read-only Barkpark change. Until it lands, tests and the transcript use `test/fake-reader.mjs`, which answers with the golden pack's `expectedHtml` and refuses any block that is not a golden. `BARKPARK_URL` is config, never an argument, so a model cannot point the server at another host. Neither it nor `BARKPARK_TOKEN` is ever echoed: a URL with a user or password, or a token that is not printable ASCII without spaces, is refused by name before any request.

## Where the port differs from Barkpark

| Case | Barkpark | Here |
|---|---|---|
| `patch-block` whose id resolves to a non-object block (`id: null`) | raises `BadMapError` | `invalid_op` |
| `1.0` where an integer is required (table row or column) | refused (`is_integer`) | accepted: JSON.parse cannot tell `1.0` from `1` |
| `field-number` text past 2^53 | exact bignum | nearest float |
| more than 32 locked blocks displaced by one op | names one in hash order | names the smallest id |
| table cells with opaque keys (shape `v: 2`) | merged | read-only: the intent is `invalid_op` |
| constraint declarations (`opts[:constraints]`) | only when a caller passes them | never; the golden harness passes none either |

## Considered

- **`McpServer` with zod schemas.** Rejected: a schema miss comes back in the SDK's words instead of naming the argument, and the size, depth and doc-shape checks are needed anyway.
- **Copy legacy `packages/mcp-server` (tag `legacy-v0.4`).** Rejected: its tools sit on the old 10-type core and render locally. Kept from it: one stdio bin, tools as plain functions the server wraps, forwarding config from env.
- **render by slug (`GET /papers/:slug`).** Rejected: it renders a stored paper, not the doc the agent just edited.
- **render locally from the goldens.** Rejected: that is not Barkpark's reader (Z9).
